# Getting Started

This guide runs Ledgerline locally and introduces the safest first workflow. The application is a **research and simulation workspace** with optional live execution capabilities. It supports wallet connection, encrypted API key management, and agent-executed trades through mandate-validated paths.

## Prerequisites

- Node.js 22+ and pnpm
- Docker and Docker Compose (recommended)
- MySQL 8.0 (or use Docker)

## Quick start with Docker (recommended)

```bash
# Clone the repository
git clone https://github.com/FrancKINANI/ai-investment-agent.git
cd ai-investment-agent

# Copy environment file
cp .env.example .env

# Start development environment
make dev
# Or: docker-compose up
```

This starts:
- MySQL 8.0 with health checks
- App with hot reload
- Nginx reverse proxy

Access at http://localhost:3000

## Quick start without Docker

```bash
# Install dependencies
pnpm install

# Start development server
pnpm dev
```

## First safe workflow

1. Open **Command** and read the fail-closed authority strip.
2. Open **Settings** to review protected agent routes, optional specialists, and inactive discovery schedules. Changing a model route does not add a tool scope or financial authority.
3. Use **Chat** to give the supervisor a research brief. Bull and Bear views are evidence discussion, not trade instructions.
4. Create a watchlist in **Command** and use the Evidence Lab only with a valid public Ethereum contract address.
5. Review paper-proposal states and the immutable **Activity** log. Owner approval is required before simulated settlement.
6. Visit **Wallets** to connect a wallet and explore mode management (Simulation → Paper → Live).
7. Visit **Platforms & API Keys** to add an exchange API key with trading-only permissions.
8. Visit **Mandates** to create Sailor Protocol mandates for on-chain execution.
9. Check **Security Alerts** for any alerts generated by your actions.

## Wallet connection

### Connect a wallet

1. Go to **Wallets**
2. Click **Connect Wallet**
3. Choose WalletConnect (QR code) or injected provider (MetaMask)
4. Approve the connection in your wallet
5. View connected address, network, and balances

### Mode management

- **Simulation** (default): No real execution
- **Paper**: Simulated execution with real market data
- **Live**: Real execution with mandate validation

To enable Live mode:
1. Connect a wallet
2. Create a Sailor mandate
3. Click **Enable Live Mode**
4. Confirm in the dialog

## API key management

### Add an API key

1. Go to **Platforms & API Keys**
2. Click **Add API Key**
3. Select platform (Binance, OKX, Coinbase, Kraken)
4. Enter API key and secret
5. Set permissions (trading-only recommended)
6. Configure limits (max order, allocated capital)

### Security

- Secrets are encrypted with AES-256-GCM
- Only key prefix is stored for identification
- Withdrawal permissions trigger critical alerts
- All operations are audit-logged

## Agent execution

Agents can execute trades through two paths:

### CEX execution (Binance)

```
Agent proposal → mandate check → Binance API → order → audit log
```

### On-chain execution (Sailor)

```
Agent proposal → mandate check → WalletConnect → owner signs → broadcast → log
```

Both paths require:
- Active mandate (real or armed mode)
- Order/value caps within mandate limits
- Immutable audit logging

## Authentication and data states

Signed-in workspaces load owner-scoped data. A loading skeleton means a request is still in progress; an empty state means that no relevant owner data exists. Do not treat a loading state as a policy, connection, balance, or execution result.

## Database changes

For a schema change, update `drizzle/schema.ts`, generate a migration, inspect it, and apply it through the managed database workflow. Do not store file bytes, secrets, or wallet material in the database. New tables should follow the existing owner-scoped, auditable patterns.

```bash
# Push schema changes
make db-push
# Or: docker-compose exec app pnpm db:push

# Reset database (WARNING: destroys data)
make db-reset
```
