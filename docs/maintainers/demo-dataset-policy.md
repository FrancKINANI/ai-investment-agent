# Open-Source Demo Dataset Policy

Ledgerline is a simulation-first workspace. Any sample data, fixture, development seed, screenshot, documentation example, or test record must reinforce that boundary rather than obscure it.

## Allowed examples

Use clearly labelled synthetic identifiers, neutral placeholder amounts where needed for a layout test, public contract addresses only when source attribution and timing are explicit, and deterministic test fixtures that cannot be mistaken for customer activity. Mark non-production material with language such as **sample**, **synthetic**, **fixture**, or **simulation-only**.

## Prohibited examples

Do not include customer data, account information, balances, private portfolio holdings, orders, fills, connected venues, wallet addresses tied to a person, credentials, API responses containing secrets, seed phrases, private keys, proprietary research, or unverified performance claims. Do not create fake testimonials, reviews, ratings, trade histories, or returns.

## Screenshots and documentation

Screenshots must use empty, loading, explicitly synthetic, or public-safe states. Blur or omit personal identifiers. Do not represent an unauthenticated placeholder as a real account, and do not publish a simulated proposal in a way that implies it was sent to a live venue.

## Review checklist

Before merging demo material, confirm that it contains no sensitive data, declares its synthetic or public-source status, keeps simulation labels visible, and does not bypass the policy, credential, custody, or execution boundaries described in the security documentation.
